# Coding Rules

## JWT Auth Rules
- All protected backend routes must use JWT verification middleware.
- JWT tokens should be securely handled on the frontend and included in the `Authorization` header as a Bearer token.
- Passwords must be hashed using `bcrypt` before storing in the database.

## Error Handling Patterns
- Use centralized error handling middleware in Express to catch and format errors consistently.
- Frontend must gracefully handle API errors, displaying user-friendly messages rather than raw stack traces.
- Backend must never leak internal stack traces or database error details to the frontend.

## Environment Variable Rules
- **NEVER** expose `GEMINI_API_KEY` to the frontend. All AI interactions must occur on the backend.
- **NEVER** expose the Supabase `SERVICE_ROLE_KEY` to the frontend. 
- Use `.env` files for local development and securely configure environment variables in Vercel and Render for production.

## Zod Validation
- **Required:** All responses generated by the Gemini AI must be parsed and validated using Zod before being processed further or sent to the frontend.
- API request payloads (body, query, params) must be validated using Zod schemas in backend routes.
